# ADR 011: 데이터 패키징 표준 — RO-Crate 채택

> **Date:** 2026-10-27
> **Status:** Accepted

---

## 배경

연구개발계획서 3차년도 "신뢰성 보장 데이터 패키징", 4차년도 "능동형 데이터 패키징" 과업은
데이터셋을 외부에 제공할 때 **출처·무결성·이용조건이 보장되는 패키지**를 요구한다.

자체 포맷을 설계할 수도 있으나, 과제 평가 관점에서 **국제 표준 차용이 유리**하다.

## 선택지

| 표준 | 라이선스 | 판정 |
|---|---|---|
| **RO-Crate 1.2** (`rocrate`) | 라이브러리 Apache-2.0 | **채택** |
| Frictionless Data Package v2 | 라이브러리 MIT | 탈락 — **표 형식 중심**. 우리는 영상·뉴스·블로그 등 비정형 혼재이고 이미 DCAT/JSON-LD를 쓰므로 **어휘만 하나 더 늘어난다.** 리니지(PROV-O) 표현 불가 |
| BagIt (RFC 8493) | — | **부분 차용** — 체크섬·디렉터리 규약만 정의하고 **의미 메타데이터가 전혀 없어** 단독으로는 "신뢰성 보장"이 성립하지 않는다. `manifest-sha256.txt` 1장만 차용(외부 도구 호환성) |
| OCFL | — | 탈락 — 리포지터리 전체의 버전 관리 레이아웃 표준. "외부 제공용 패키지 1건"과 목적이 다르다 |

## 결정

**RO-Crate를 패키지 표준으로 채택한다.**

1. **JSON-LD + schema.org 기반**이라 기존 [`src/storage/jsonld_export.py`](../../src/storage/jsonld_export.py)의
   @context·엔티티 구조를 거의 그대로 재사용할 수 있다.
2. **PROV-O 리니지를 `CreateAction`으로 표준 어휘로 담을 수 있다** —
   이미 운영 중인 `dcat_provenance`를 그대로 매핑한다.
3. 엔티티 단위 `license` 지정이 가능해 이용조건 보장 요구를 충족한다.
4. ZIP/BagIt 어디에 담아도 되는 중립 포맷이다.
5. `conformsTo`로 버전을 명시하므로 나중에 올리기 쉽다. 기준 버전은 **1.2로 고정**한다.

### 무결성·서명

| 방식 | 판정 |
|---|---|
| SHA-256 매니페스트 | **필수 채택** — 비용 0, 외부 검증 용이 |
| **Ed25519 분리 서명** | **채택(목표선)** — 개인키는 K8s Secret, **공개키만 배포**. `key_id`로 키 회전 대응 |
| HMAC(공유키) | **탈락** — 검증하려면 **수신자에게 비밀키를 넘겨야 한다.** 외부 배포에 구조적으로 부적합하고 유출 시 위조 가능 |
| Sigstore/cosign | 탈락 — OIDC IdP + 공개 투명성 로그(Rekor) 전제. 폐쇄망 자체 호스팅은 과제 규모 대비 과함 |

HSM·Vault는 도입하지 않는다(현 단계 과잉). 개인키가 K8s Secret에 있다는 점은
**받아들이는 위험**으로, RBAC로 접근 주체를 좁히고 키 회전 절차를 문서화한다.

### "능동형"의 해석

패키지를 미리 만들어 두지 않고, **요청(`purpose` + `selector`)을 입력으로 그때그때 조립**한다.
목적별 프로파일이 포함 데이터셋·컬럼, 마스킹 규칙, 부여 라이선스를 다르게 결정한다.

## 한계

⚠️ **국내 공공데이터 맥락에서 RO-Crate 적용 사례·지침은 확인되지 않았다.**
과제 문서에서는 **"국제 연구데이터 패키징 표준 차용 + 국내 공공데이터 메타데이터 표준과의
매핑 테이블 제공"** 형태로 포지셔닝한다. 매핑 테이블을 별도 산출물로 준비한다.

⚠️ `rocrate` 라이브러리는 아직 0.x → **버전 핀 고정 필수**, 업그레이드 시 회귀 테스트.
