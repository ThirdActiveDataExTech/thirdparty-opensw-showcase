# ADR 016: 임베딩 모델과 적재 규약 — multilingual-e5-base

> **Date:** 2026-10-29
> **Status:** Accepted
> **Supersedes:** [ADR-003](003_VectorDB_Strategy.md) §임베딩 모델 (pgvector·Qdrant 전략은 유효)

---

## 배경

ADR-003은 `paraphrase-multilingual-mpnet-base-v2`(768차원)를 채택했다.
선정 근거는 "가볍고 안정적, 가장 널리 쓰임"이었고, **검색 품질을 실측하지 않았다.**

2026-10-28 임베딩 33,903건을 적재한 뒤 검색이 동작하지 않는 것을 확인했다.
형식 검증(커버리지 100%, 차원 768, 자기 유사도 1.0)은 전부 통과한 상태였다.

이후 세 가지 독립된 원인이 순차적으로 드러났다.

| # | 원인 | 증상 |
|---|---|---|
| 1 | **MPS 배치 인코딩 손상** | 동일 텍스트의 단건·배치 인코딩 결과가 cos **0.0073** |
| 2 | **통짜 임베딩** | 제목이 글자까지 같은 문서가 29,029건 중 **17,449위** (cos 0.2257) |
| 3 | **모델 용도 불일치** | 패러프레이즈용 모델이라 짧은 질의 ↔ 긴 문서 비대칭에 약함 |

각각은 독립적으로 기여했고, 하나만 고쳐서는 해결되지 않았다.

## 결정

### 1. 모델

**`intfloat/multilingual-e5-base` (768차원)로 교체한다.**

e5는 질의-문서 비대칭 검색용으로 대조학습된 모델이다. 차원이 768로 같아
**DDL·인덱스를 변경하지 않는다.** 인코딩은 약 20% 느려진다.

동일 코퍼스(1,200건)·동일 질의·동일 청킹 조건 실측:

| 질의 | 이전 모델 | **e5-base** |
|---|---|---|
| 치질 수술 후 주의사항 | 7위 | **1위** |
| 위암 조기 진단 | 4위 | **1위** |
| HBM 고대역폭 메모리 | 3위 | **1위** |
| 대장내시경 검사 | 1위 | 2위 |

### 2. 프리픽스 — 필수 규약

| 용도 | 프리픽스 |
|---|---|
| 문서 색인 | `passage: ` |
| 질의 | `query: ` |

⚠️ **누락해도 오류가 나지 않는다.** 검색 품질만 조용히 떨어진다.
`embedder.encode()`가 기본으로 `passage: `를 붙이고, 질의는 반드시
`encode_query()`를 쓴다. `embed_text` 컬럼에는 **프리픽스를 제외한 원문**을 저장한다.

### 3. 실행 디바이스 — CPU 고정

`EMBEDDING_DEVICE` 기본값을 `cpu`로 둔다. Apple Silicon MPS에서 **배치 인코딩 시
벡터가 손상**되기 때문이다(동일 텍스트 단건 대비 cos 0.0073).

모델 로딩 시 `self_check()`가 같은 문장을 단건·배치로 인코딩해 cos < 0.999면
`RuntimeError`를 던진다. **커버리지·차원·자기 유사도가 모두 통과해도 벡터 내용이
무의미할 수 있다**는 것이 이번 사건의 교훈이고, 이를 구조로 고정한 것이다.

### 4. 입력 분할(청킹)

본문은 통짜로 넣지 않는다. 문장·줄 단위로 쪼개 기본 80자 단위 청크로 적재하고,
검색은 **청크 최대 유사도**로 집계한다. 상세 근거와 실측은
[database/embedding_chunking.md](../database/embedding_chunking.md).

```
MAX_SEQ_LENGTH = 512   # e5 학습 상한 (이전 모델은 128이라 긴 본문이 잘렸다)
DEFAULT_SIZE   = 80    # 청크 크기
```

### 5. 집계 — 평균이 아니라 최대값

```sql
SELECT key, MAX(1 - (embedding <=> :q)) AS score FROM {tbl} GROUP BY key
```

긴 문서에서 질의와 맞는 청크가 1개, 무관한 청크가 10개일 때
**평균은 정답 신호를 희석시킨다.**

### 6. 거리·정규화

코사인(`vector_cosine_ops`), L2 정규화 후 적재. `model_name` 컬럼에는
HuggingFace 식별자 전체를 기록해 모델 교체 시 재임베딩 대상을 가린다.

## 받아들이는 대가

- 인코딩 약 20% 저하. 전량 재생성은 160,142청크 기준 수용 가능한 범위였다.
- **분류(category zero-shot)는 모델 교체로 해결되지 않는다.** 합성 8건 테스트에서
  두 모델 모두 Top-1 3/8로 같았다. 다만 `theme`이 포함된 실데이터에서는 e5가
  명확히 개선됐다(반도체 채널: 문화>만화 → 기술>전기·전자). **합성 테스트가 실제
  사용 조건과 달랐던 것**이며, 분류의 근본 개선은 sLLM 전환 과제로 남긴다.

## 외부 영향 — 정형 데이터 연계

`relation_type_registry`의 `SEMANTICALLY_RELATED`는 `applies_to = ["*"]`로
**정형·비정형 교차 비교를 전제한다.** 모델이 다르면 차원이 768로 같아도 벡터
공간이 달라 코사인 유사도가 무의미해지며, **오류 없이 그럴듯한 숫자가 나온다.**

현 DDL 주석에 "정형·비정형 임베딩 모델 통일 여부는 협의 미결"로 남아 있다.
이 ADR을 근거 자료로 통일을 제안한다
(database/vec_schema_unification_proposal.md §4).

## 재검토 조건

- 한국어 특화 모델(`jhgan/ko-sroberta-multitask` 등)이 같은 벤치마크에서 우위를 보일 때
- 코퍼스가 커져 768차원·HNSW로 응답 시간을 맞추지 못할 때 (ADR-003의 Qdrant 전환 경로)
- 협력기관과 다른 모델로 합의될 때 — **그 경우 전량 재임베딩이 필요하다**
